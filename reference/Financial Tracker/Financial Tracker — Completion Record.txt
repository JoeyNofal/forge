Vault Financial Tracker — Complete Project Record
What We Started With
A web-based HTML financial tracker built with Kiro AI. It was a multi-file project (index.html + separate JS modules + CSS) that ran in the browser using localStorage for data storage. It had 7 views: Dashboard, Forecast, Inputs, Settings, Paychecks, Ledgers, and Groceries.
Original capabilities:

Account tracking: VAULT, FLEX, FUNDS (with Car Fund and Savings Fund sub-accounts), CC, Car Loan
VAULT buffer calculator targeting 7 months of expenses + $1,500
FLEX allowance calculator (weekly fixed expenses + groceries + CC balance, rounded to nearest $10)
FUNDS reallocation engine (50/50 split, Car Fund rounded down to nearest $500)
Priority-based allocation recommender (P1: VAULT buffer, P2: Car Fund to $1,500, P3: Savings +$100)
Paycheck predictor using average tax rates from approved paychecks
52-week forecast
Fixed expense tracking
Grocery tracking from September 2024
Transaction ledgers with undo support
Work schedule calculator (Mon/Tue/Wed 12hrs each, alternating Sundays)
Credit score tracking (single source)
Excel export
Description autocomplete

Original limitations:

Browser-only, localStorage meant data was lost if browser was cleared
No AI chatbot
CORS blocked any direct API calls
All data stored in localStorage, not portable
Single credit card (CC), no naming
Single credit score source
No real-time tax calculation in paycheck modal
Forecast was broken/unreliable

Phase 4 — Debugging the Chatbot (Long Journey)
This was the most complex debugging session. Issues encountered and resolved:

Chat panel taking up space when closed — fixed by changing from CSS transform to position: fixed overlay
API not responding — multiple root causes found:

package.json had wrong "main": "index.js" from npm init, so main.js never ran, preload.js never loaded, window.electronAPI was never defined
The app was silently falling through to browser copy-paste mode


renderConvList() resetting currentConvId to null — found by tracing the call chain: send() → newConversation() → openConversation() → switchBot() → renderConvList() → sets currentConvId = null. Fixed by rewriting send() to not rely on newConversation().
innerHTML += destroying DOM — every time a message was appended using innerHTML +=, it destroyed and recreated all existing DOM elements including the thinking indicator, causing stale references. Fixed by switching to appendChild.
Old send() function persisting — Notepad edits weren't taking effect because the renamed function (send_PLACEHOLDER) had to be restored to send().
Anthropic API key — went through environment variables approach, then switched to storing key directly in App.data.settings.anthropicApiKey and passing it to main process via IPC. The main process checks env var first, then falls back to settings key.
Billing issue — original Anthropic account had wrong phone number (organization account). Resolved by creating new personal account at console.anthropic.com and adding $5 credits.

Final working chat architecture:

User types message → App.chat.send() runs
Checks window.electronAPI exists and API key is set
Builds full system prompt with all financial data
Calls window.electronAPI.claudeAPI({systemPrompt, messages, apiKey})
preload.js forwards to ipcRenderer.invoke('claude-api', ...)
main.js makes native HTTPS request to api.anthropic.com
Response returns through IPC chain back to renderer
Message appended to chat panel via appendChild

Key Technical Notes for Next Session

Always use Command Prompt, never PowerShell — PowerShell blocks npm/npx due to execution policy
Launch command: cd C:\Users\youss\Documents\FinancialTracker && npx electron .
Edit files with Notepad (Ctrl+H for find/replace, Ctrl+G for go to line)
After every Notepad edit: Ctrl+S to save, then restart app
DevTools: enabled in main.js — a separate DevTools window opens with the app for debugging
API key: stored in App.data.settings.anthropicApiKey, set via Settings → AI Chatbot section
Arrow functions in Chart.js options cause syntax errors in this context — always use function(v){return ...} format instead of v=>... for callbacks inside chart config objects
innerHTML += destroys DOM — always use appendChild for adding chat messages
package.json must have "main": "main.js" — npm init creates "main": "index.js" by default which breaks everything
FUNDS split formula: Car Fund = Math.floor(fundsBalance / 2 / 500) * 500, Savings = remainder
Tax rate calculation: average rates from same-year approved paychecks → all-time approved → hardcoded defaults
